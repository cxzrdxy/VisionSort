# VisionSort · 工业视觉分拣上位机

基于 **Cognex VisionPro 9.0** 的视觉引导机械臂自动分拣上位机：传送带送料 → 光电硬触发相机取像 →
PatMax 模板定位与 OK/NG 判定 → 九点标定把像素坐标换算成机械臂毫米坐标 → NG 件由机械臂抓取分拣 →
MySQL 落库 + Excel 导出，全流程无人干预。

`C#` · `.NET Framework 4.8` · `WinForms` · `x64` · `Cognex VisionPro 9.0 CR2` · `GigE Vision` ·
`Modbus RTU` · `MySQL 8.0` · `P/Invoke` · `多线程状态机`

```text
VisionSort.exe   (x64 / .NET Framework 4.8 / WinForms)
|
|-- 5 个功能页
|     主运行 / 设备调试 / 视觉配置 / 数据日志 / 系统设置
|
|-- 服务层
|     ProductionRunner      生产主循环状态机 (跑在后台线程)
|     VisionScheme          VPP 加载 / PatMax 定位与判定 / 模板原点核对
|     PmaTemplateTrainer    PatMax 模板训练与自检
|     CalibrationService    九点标定: 拟合 / 精度指标 / 手性校验 / 像素 -> 毫米
|     CameraService         共享 GigE 取像 FIFO (两个页面共用一个相机)
|     ConveyorSettings      传送带 Modbus RTU 主站 (信号量串行化)
|     ResultRepository      写库队列 + 断网补写 + 幂等重试
|     ImageSaver / XlsxWriter          检测图落盘 / 零依赖 xlsx 导出
|     RobotPickPlace / RobotArmService NG 分拣动作 / 机械臂连接管理
|
+-- 外部连接
      GigE Vision                --> 工业相机
      Modbus RTU (9600-8-N-1)    --> 传送带变频器 (站号 2, 寄存器 100/101/102)
      ADO.NET (MySqlConnector)   --> MySQL 8.0 (vision_sort.vision_result)
      回环 UDP 127.0.0.1:18899   --> DobotArmBridge.exe (x86, 独立进程)
        |   自研 KV 线协议, 12 条命令, 一问一答 + seq 校验
        |
        +-- 宿主官方 DobotDll.dll + Qt5x3 + MSVCx2 (共 6 个原生依赖)
        +-- 崩溃也带不走 x64 主程序; 可脱离主程序单独启动手工验证
        |
        +-- USB 串口 115200-8-N-1 --> Dobot Magician 四轴机械臂
```

设计要点：

- **x64 主程序零原生依赖**，唯一接触 32 位机器人原生 DLL 的地方是独立的 x86 桥接进程。
- **桥接进程可脱离主程序单独启动**，用一行文本报文即可手工验证，现场排障成本低。
- 视觉得到的是**像素坐标**，经九点标定换算成机械臂毫米坐标后，取料点不再写死——工件停在哪儿都能抓。

## 三、技术难点

### 1. x64 视觉库 × 32 位机器人原生 DLL 的位数隔离

VisionPro 9.0 是 x64 混合模式程序集，而 Dobot 官方 `DobotDll.dll` 只有 32 位版本（PE 头
`Machine=0x014C`），还连带 Qt5×3 + MSVC×2 共 6 个原生依赖，且只提供 USB 串口接口、没有网络接口。

**关键判断：拆成独立类库并不能隔离。** 类库仍然被加载进 `VisionSort.exe` 进程，它 P/Invoke 的原生 DLL
也进同一进程——拆项目只解决编译期，运行时 x64 进程加载 x86 库必然 `BadImageFormatException`。
**必须用独立进程隔离。**

因此新增 x86 控制台进程承载全部原生调用，两侧用**自研回环 UDP 线协议**通信：

```
请求：cmd=moveJ;seq=7;x=200.0000;y=30.0000;z=-50.0000;r=0.0000
应答：ok=1;seq=7
失败：ok=0;seq=7;err=NOT_FOUND;msg=没找到机械臂：确认 USB 线已插
```

12 条命令（ping/search/connect/disconnect/pose/alarms/clearAlarms/home/moveJ/jog/suction/shutdown），
可靠性设计：一问一答信号量串行化、递增 `seq` 校验并丢弃迟到包、**仅对幂等命令**超时重发（动作命令
绝不盲目重发）、断线即标记并触发事件、连接失败后主动 `disconnect` 对账。

工程防呆：协议源码双端 Link 同一份文件；MSBuild 目标 `EnsureX86` 在编译前硬校验平台，防止被
ProjectReference 传入的 x64 静默带错；桥接程序与原生依赖用构建后 `Target` 拷贝，规避"项目评估 glob
时桥接尚未构建 → 静默漏拷"的部署坑。

### 2. 视觉标定中三处"程序不报错、结果全错"的静默失效

这类问题人眼从数字上看不出来，只能由程序拦，现已全部转成程序化校验与中文提示：

| 现象 | 原因 | 处理 |
|---|---|---|
| 判定 OK/NG 正常，但机械臂抓的位置整体偏掉，**无任何报错** | PatMax 输出的"位置"是**模板原点**在图像中的位置，而原点默认值是 (0,0)，即图像左上角，不是工件 | 训练后与标定计算前强制核对原点，不通过不允许保存 |
| 标定的"精度"差了 27 倍 | `CogCalibNPointToNPointTool` 的两个 `GetComputed...Transform()` 返回的都是「未校正 ← 已校正」（像素 ← 毫米），要「像素 → 毫米」**必须 Invert** | 统一走反变换，并把反变换 `Scaling` 作为 mm/px 显示 |
| 机械臂往反方向走 / 分拣从不动作 | ① 反变换矩阵行列式为负说明 X/Y 有一个轴配反了（镜像）；② PMA 的 `AcceptThreshold` 会**把结果从结果集里直接滤掉**，判 NG 时取不到像素坐标 | ① 用行列式判手性，镜像时**拒绝保存**；② 生产固定用 `AcceptThreshold=0`，判定由程序自己算 |

实测：同一张分数 0.9401 的图，阈值设 0.90 时 `Results.Count` 直接变成 **0**（不是"结果在、
Accepted=false"，是根本没有结果）——这正是"NG 时机械臂永不动作"的根因。

### 3. 生产节拍不能被任何一步挂死

主循环跑在后台线程（Auto 硬触发下取一帧要阻塞等光电，放在 UI 线程上"急停"按钮就按不动了），
并逐格定义异常策略：

- 写库失败、存图失败 → **只记备注，不打断节拍**；
- 机械臂异常 → **仍然写库**（不丢事件），中文原因写进记录备注；
- 取像失败 → 连续多次才判故障（连续模式等不到工件属正常）；
- 检测加 2000ms 看门狗，超时则本轮仍落记录后停线等人；
- 急停 = 取消令牌 + 停带 + 状态锁存，**不自动恢复**；
- 恢复传送带只写启停寄存器，**不碰速度寄存器**。

数据链路上，`MySqlConnection` 非线程安全 → 每次操作各自 `new` 靠连接池兜底，界面查询与后台补写
两条线永不共用连接；写库失败落 JSONL 暂存（一行一条，崩溃最多丢最后半行），DB 恢复后自动补齐；
每行带客户端生成的 `uuid`，表上 `UNIQUE KEY` + `INSERT IGNORE`，**重试不产生重复行**。

## 四、构建与运行

### 前置条件

- Visual Studio 2019 及以上，**.NET Framework 4.8** 开发包
- **Cognex VisionPro 9.0**（本工程通过 `HintPath` 引用其 `ReferencedAssemblies\` 下的程序集；
  安装路径与 `VisionSort.csproj` 中的 HintPath 不一致时需要改路径）
- 解决方案平台必须选择 **x64**（`DobotArmBridge` 自身必须是 x86，构建期有硬门槛会拦截错误平台）

### 依赖说明

`NuGet.Config` 已清空包源，**全部依赖走本地文件引用**，可离线还原：

- `VisionSort\Libs\NModbus.dll`（NModbus 3.0.83，Modbus RTU）
- `VisionSort\Libs\mysql\*.dll`（MySqlConnector 2.4.0 及其 net48 依赖闭包，共 10 个 DLL）
- `DobotArmBridge\deps\*.dll`（官方 `DobotDll.dll` + Qt5×3 + MSVC×2，构建后自动拷到输出目录 `ArmBridge\`）

### 运行前准备

- `vpps\` —— 放入 QuickBuild 导出的 `.vpp` 视觉方案
- `config\` —— `sysparam.json`（参数，程序内保存生成）、`calib.json`（标定结果）、
  `pending_results.jsonl`（断网补写暂存）
- 图像保存根目录默认为 `D:\VisionData`，可在「视觉配置 → 图像保存配置」修改

## 五、现场排错备忘

| 现象 | 先查 |
|---|---|
| 相机预览一片空白（像"蓝屏"） | **GigE 包大小**：写死 9000 但网卡没开巨帧 → 一帧都来不了。标准 1500 MTU 用 **1508** |
| 相机连上但取不到图 | 触发方式。现场那台需按「保持原配置 → FreeRun → Manual」依次试取，哪种出图用哪种 |
| 机械臂静默地抓偏一个固定量 | **模板原点**没设（默认在图像左上角） |
| 离画面中心越远越偏 | 标定高度与生产抓取高度不一致，或九个点没铺开 |
| 左右/上下反了 | X/Y 对错轴了（看标定区的"手性"指标） |
| 刚点正转但回读还是停止 | 串口并发串包（主站非线程安全，已用信号量串行化） |

九点标定的完整操作步骤见 [`九点标定操作指引.md`](九点标定操作指引.md)
（该文件同时以嵌入资源编译进 `VisionSort.exe`，程序内「操作指引」按钮弹出的就是同一份）。
